# 收藏模块后端开发指导

本文最初用于分阶段指导收藏模块的后端开发。数据模型由你完成并经过审查，其余功能现已按相同约定实现；文末补充了实际代码示例，便于逐段对照学习。

## 1. 已确认的产品规则

- 前台模块名称为“收藏”。
- 前台页面路径为 `/bookmarks`。
- 分类最多两级：一级分类和二级分类。
- 收藏必须归属二级分类，不能直接归属一级分类。
- 收藏包含名称、描述、图标 URL 和网站 URL。
- 不提供本地图片上传。
- 图标 URL 可以为空；为空或图片加载失败时，由前端显示默认占位图标。
- 网站 URL 必填。
- 同一个网站 URL 不允许重复收藏。
- 删除非空分类时应拒绝操作，不能级联误删收藏。

## 4. 第一阶段：Prisma 数据模型

### 4.1 `BookmarkCategory` 应包含的字段

| 字段 | 建议类型 | 说明 |
| --- | --- | --- |
| `id` | `Int` | 自增主键 |
| `name` | `String` | 分类名称，建议限制为 50 字符 |
| `parentId` | `Int?` | 一级分类为空；二级分类指向一级分类 |
| `parent` | 自关联 | 当前分类的父分类 |
| `children` | 自关联数组 | 当前分类的子分类 |
| `bookmarks` | 关联数组 | 归属于该分类的收藏 |
| `sort` | `Int` | 排序值，默认 0 |
| `createdAt` | `DateTime` | 创建时间 |
| `updatedAt` | `DateTime` | 更新时间 |

自关联需要显式命名 relation，父级删除策略使用 `Restrict`。

建议索引：

- `parentId + sort`
- `sort + id`

分类名称应在同一个父分类下保持唯一。可以增加组合唯一约束，但需要注意：PostgreSQL 会把多个 `NULL` 视为互不相同，因此一级分类重名还需要在业务层额外检查。

### 4.2 `Bookmark` 应包含的字段

| 字段 | 建议类型 | 说明 |
| --- | --- | --- |
| `id` | `Int` | 自增主键 |
| `categoryId` | `Int` | 必填，必须指向二级分类 |
| `category` | 关联 | 所属分类，删除策略使用 `Restrict` |
| `name` | `String` | 收藏名称，建议限制为 100 字符 |
| `description` | `String` | 收藏描述，建议限制为 500 字符 |
| `iconUrl` | `String?` | 图标 URL，最长 2048 字符 |
| `url` | `String` | 网站 URL，最长 2048 字符且唯一 |
| `sort` | `Int` | 排序值，默认 0 |
| `isVisible` | `Boolean` | 是否公开，默认 `true` |
| `createdAt` | `DateTime` | 创建时间 |
| `updatedAt` | `DateTime` | 更新时间 |

建议索引：

- `categoryId + sort`
- `isVisible + sort`

### 4.3 Prisma 无法直接保证的规则

以下规则不能只依赖 Prisma Schema，必须由 API 业务逻辑校验：

- 分类不能超过两级。
- 父分类必须是一级分类。
- 分类不能把自己设为父分类。
- 分类更新不能形成环。
- 收藏只能关联二级分类。
- 有子分类的一级分类不能变成二级分类。
- 已经包含收藏的二级分类不能变成一级分类。

- [ ] 自关联字段完整且 relation 名称一致。
- [ ] 两个外键都使用安全的删除策略。
- [ ] URL、名称和描述具有合理的数据库长度限制。

- `categoryId`：正整数。

- `description`：去除首尾空格，长度 1～500。

## 7. 第四阶段：收藏分类后台 API

### 7.1 接口列表

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/admin/bookmark-categories` | 获取完整分类树和数量 |
| `POST` | `/api/admin/bookmark-categories` | 创建一级或二级分类 |
| `PUT` | `/api/admin/bookmark-categories/:id` | 修改分类 |
| `DELETE` | `/api/admin/bookmark-categories/:id` | 删除空分类 |

### 7.2 创建分类时的校验顺序

1. 使用 Zod 校验请求体。
2. 如果 `parentId` 为空，则创建一级分类。
3. 如果 `parentId` 有值，查询父分类。
4. 父分类不存在时返回 `404`。
5. 父分类本身还有父级时返回 `409`，防止创建三级分类。
6. 检查同级分类名称是否重复。
7. 创建并返回数据，状态码为 `201`。

### 7.3 更新分类时必须检查

- 分类是否存在。
- `parentId` 是否指向自身。
- 新父分类是否存在。
- 新父分类是否为一级分类。
- 修改是否会形成循环关系。
- 有子分类的分类不能再成为二级分类。
- 有收藏的二级分类不能改成一级分类。
- 新位置是否已经有同名分类。

涉及多次读取与写入时，建议使用 Prisma transaction，避免校验完成后数据被并发修改。

### 7.4 删除分类时必须检查

- 分类不存在：返回 `404`。
- 一级分类仍有子分类：返回 `409`。
- 二级分类仍有收藏：返回 `409`。
- 只有空分类可以删除，成功返回 `204`。

不要在这个功能中使用级联删除。

### 7.5 建议错误码

| 错误码 | HTTP 状态 | 场景 |
| --- | --- | --- |
| `INVALID_ID` | 400 | 路由 ID 无效 |
| `VALIDATION_ERROR` | 400 | 请求体校验失败 |
| `BOOKMARK_CATEGORY_NOT_FOUND` | 404 | 分类不存在 |
| `BOOKMARK_CATEGORY_CONFLICT` | 409 | 同级名称重复 |
| `BOOKMARK_CATEGORY_DEPTH_EXCEEDED` | 409 | 尝试创建三级分类 |
| `BOOKMARK_CATEGORY_NOT_EMPTY` | 409 | 删除非空分类 |
| `BOOKMARK_CATEGORY_INVALID_PARENT` | 409 | 父级非法或形成循环 |

错误响应继续使用现有 `apiError()` 和 `zodFields()`。

## 8. 第五阶段：收藏后台 API

### 8.1 接口列表

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/admin/bookmarks` | 获取收藏，可按分类筛选 |
| `POST` | `/api/admin/bookmarks` | 新增收藏 |
| `PUT` | `/api/admin/bookmarks/:id` | 修改收藏 |
| `DELETE` | `/api/admin/bookmarks/:id` | 删除收藏 |

### 8.2 创建和更新收藏的校验顺序

1. 使用 Zod 校验请求体。
2. 查询 `categoryId` 对应分类。
3. 分类不存在时返回 `404`。
4. 分类的 `parentId` 为空时返回 `409`，因为一级分类不能直接挂收藏。
5. 检查网站 URL 是否已存在。
6. 写入收藏。

更新时检查 URL 冲突必须排除当前收藏自身。

### 8.3 查询规则

后台列表建议支持以下可选查询参数：

- `categoryId`
- `q`：名称、描述或 URL 模糊查询
- `visible`

列表结果应包含所属二级分类，以及它的一级分类名称，方便后台直接展示完整路径。

### 8.4 建议错误码

| 错误码 | HTTP 状态 | 场景 |
| --- | --- | --- |
| `BOOKMARK_NOT_FOUND` | 404 | 收藏不存在 |
| `BOOKMARK_CATEGORY_NOT_FOUND` | 404 | 指定分类不存在 |
| `BOOKMARK_REQUIRES_CHILD_CATEGORY` | 409 | 尝试归属一级分类 |
| `BOOKMARK_URL_CONFLICT` | 409 | 网站 URL 已存在 |

## 9. 第六阶段：前台公开查询 API

公开接口建议为：

```text

```

接口只返回 `isVisible = true` 的收藏，并按以下顺序排序：

1. 一级分类 `sort` 升序
2. 一级分类 `id` 升序
3. 二级分类 `sort` 升序
4. 二级分类 `id` 升序
5. 收藏 `sort` 升序
6. 收藏 `id` 降序

建议直接返回前端需要的树形结构：

```json

          "name": "在线工具",
```

注意事项：

## 16. 数据模型代码示例

收藏通过 `categoryId` 关联分类，两个外键都采用 `Restrict`，避免删除分类时误删子分类或收藏：

```prisma
model BookmarkCategory {
  id        Int                @id @default(autoincrement())
  name      String             @db.VarChar(50)
  parentId  Int?
  parent    BookmarkCategory?  @relation("BookmarkCategoryParent", fields: [parentId], references: [id], onDelete: Restrict)
  children  BookmarkCategory[] @relation("BookmarkCategoryParent")
  sort      Int                @default(0)
  bookmarks Bookmark[]

  @@unique([parentId, name])
  @@index([parentId, sort])
  @@index([sort, id])
}

model Bookmark {
  id          Int              @id @default(autoincrement())
  categoryId  Int
  category    BookmarkCategory @relation(fields: [categoryId], references: [id], onDelete: Restrict)
  name        String           @db.VarChar(100)
  description String           @db.VarChar(500)
  iconUrl     String?          @db.VarChar(2048)
  url         String           @unique @db.VarChar(2048)
  sort        Int              @default(0)
  isVisible   Boolean          @default(true)

  @@index([categoryId, sort])
  @@index([isVisible, sort])
}
```

示例省略了 `createdAt` 和 `updatedAt`，完整定义以 `prisma/schema.prisma` 为准。

## 17. Zod 校验代码示例

### 17.1 只允许 HTTP/HTTPS

`.url()` 只验证字符串是否符合 URL 语法，不代表协议一定安全，因此继续检查协议：

```ts
const httpUrl = (label: string) => z.string()
  .trim()
  .min(1, `请输入${label}`)
  .max(2048)
  .url(`${label}格式不正确`)
  .refine((value) => {
    const protocol = new URL(value).protocol
    return protocol === 'http:' || protocol === 'https:'
  }, `${label}只支持 HTTP 或 HTTPS`)
```

### 17.2 把空图标转换成 `null`

数据库使用 `null` 统一表示没有图标，避免同时出现空字符串和 `null`：

```ts
const nullableIconUrl = z.union([
  z.literal(''),
  z.null(),
  httpUrl('图标 URL'),
]).transform(value => value || null)
```

## 18. 分类业务规则代码示例

### 18.1 阻止第三级分类

创建二级分类时先读取父分类。如果父分类本身已经有父级，说明继续创建会产生第三级：

```ts
const parent = await tx.bookmarkCategory.findUnique({
  where: { id: input.parentId },
})

if (!parent) {
  // 返回 404 BOOKMARK_CATEGORY_NOT_FOUND
}

if (parent.parentId !== null) {
  // 返回 409 BOOKMARK_CATEGORY_DEPTH_EXCEEDED
}
```

### 18.2 为什么一级分类重名要额外查询

PostgreSQL 的普通联合唯一约束会把不同的 `NULL` 看成互不相同，因此下面的数据库约束主要保证二级分类同级不重名：

```prisma
@@unique([parentId, name])
```

创建和更新接口仍然显式查询，包括 `parentId = null` 的情况：

```ts
const duplicate = await tx.bookmarkCategory.findFirst({
  where: {
    parentId: input.parentId,
    name: input.name,
  },
  select: { id: true },
})
```

### 18.3 删除前检查内容

```ts
const category = await tx.bookmarkCategory.findUnique({
  where: { id },
  include: {
    _count: { select: { children: true, bookmarks: true } },
  },
})

if (category._count.children > 0 || category._count.bookmarks > 0) {
  // 返回 409 BOOKMARK_CATEGORY_NOT_EMPTY
}
```

应用层检查用于给出清晰错误提示，数据库中的 `onDelete: Restrict` 则是最后一道保护。

## 19. 收藏业务规则代码示例

Prisma Schema 只能保证 `categoryId` 指向一个存在的分类，不能判断它是不是二级分类，所以接口还需要检查 `parentId`：

```ts
const category = await tx.bookmarkCategory.findUnique({
  where: { id: input.categoryId },
})

if (!category) {
  // 返回 404 BOOKMARK_CATEGORY_NOT_FOUND
}

if (category.parentId === null) {
  // 返回 409 BOOKMARK_REQUIRES_CHILD_CATEGORY
}
```

网站 URL 的重复写入由数据库唯一索引兜底，并把 Prisma 的 `P2002` 转换为业务错误：

```ts
if (error instanceof Prisma.PrismaClientKnownRequestError && error.code === 'P2002') {
  return apiError(event, 409, 'BOOKMARK_URL_CONFLICT', '该网站 URL 已经收藏')
}
```

## 20. 公共接口嵌套查询示例

公开接口一次查询出完整树形数据，并在数据库层过滤隐藏收藏和空分类：

```ts
const categories = await prisma.bookmarkCategory.findMany({
  where: {
    parentId: null,
    children: { some: { bookmarks: { some: { isVisible: true } } } },
  },
  orderBy: [{ sort: 'asc' }, { id: 'asc' }],
  select: {
    id: true,
    name: true,
    children: {
      where: { bookmarks: { some: { isVisible: true } } },
      orderBy: [{ sort: 'asc' }, { id: 'asc' }],
      select: {
        id: true,
        name: true,
        bookmarks: {
          where: { isVisible: true },
          orderBy: [{ sort: 'asc' }, { id: 'desc' }],
          select: {
            id: true,
            name: true,
            description: true,
            iconUrl: true,
            url: true,
          },
        },
      },
    },
  },
})
```

这种写法不会随着分类数量增加而额外循环查询数据库，可以避免 N+1 查询问题。

## 21. 前端图标降级示例

后端只保存图标地址。前端记录加载失败的收藏 ID，并切换到默认图标：

```vue
<script setup lang="ts">
const brokenIcons = ref(new Set<number>())

function markIconBroken(id: number) {
  brokenIcons.value = new Set([...brokenIcons.value, id])
}
</script>

<template>
  <img
    v-if="bookmark.iconUrl && !brokenIcons.has(bookmark.id)"
    :src="bookmark.iconUrl"
    alt=""
    @error="markIconBroken(bookmark.id)"
  >
  <UIcon v-else name="i-lucide-globe-2" />
</template>
```

创建新 `Set` 而不是直接修改旧集合，是为了确保 Vue 能可靠追踪状态变化并重新渲染。
