# 收藏模块后端开发指导

本文最初用于分阶段指导收藏模块的后端开发。数据模型由你完成并经过审查，其余功能现已按相同约定实现；文末补充了实际代码示例，便于逐段对照学习。

> 2026-11-10 更新：分类已支持**任意层级嵌套**，收藏可归属**任意层级**分类；前台分类树支持折叠/展开（前端实现），后台支持收藏拖拽排序（`PATCH /api/admin/bookmarks/reorder`）。本文原先按「最多两级」写的规则已全部改写为当前实现。

## 1. 已确认的产品规则

- 前台模块名称为“收藏”。
- 前台页面路径为 `/bookmarks`。
- 分类支持任意层级嵌套，根分类的 `parentId` 为 `null`，其余指向上级分类。
- 收藏可以归属任意层级的分类（根分类也可以直接挂收藏）。
- 同一父分类下的分类名称保持唯一。
- 不允许把分类设成自己的父级，也不允许形成环。
- 收藏包含名称、描述、图标 URL 和网站 URL。
- 收藏本身不提供图片上传入口，图标只存 URL；需要自托管图片时，可以先去 `/admin/media` 上传，再把得到的链接贴进来。
- 图标 URL 可以为空；为空或图片加载失败时，由前端显示默认占位图标。
- 网站 URL 必填。
- 同一个网站 URL 不允许重复收藏。
- 删除非空分类时应拒绝操作，不能级联误删收藏。

## 4. 第一阶段：Prisma 数据模型

### 4.1 `BookmarkCategory` 应包含的字段

| 字段 | 建议类型 | 说明 |
| --- | --- | --- |
| `id` | `Int` | 自增主键 |
| `name` | `String` | 分类名称，建议限制为 50 字符 |
| `parentId` | `Int?` | 父分类；根分类为 `null`，其余指向上级分类（层级不限） |
| `parent` | 自关联 | 当前分类的父分类 |
| `children` | 自关联数组 | 当前分类的子分类 |
| `bookmarks` | 关联数组 | 归属于该分类的收藏 |
| `sort` | `Int` | 排序值，默认 0 |
| `createdAt` | `DateTime` | 创建时间 |
| `updatedAt` | `DateTime` | 更新时间 |

自关联需要显式命名 relation，父级删除策略使用 `Restrict`。

建议索引：

- `parentId + sort`
- `sort + id`

分类名称应在同一个父分类下保持唯一。可以增加组合唯一约束，但需要注意：PostgreSQL 会把多个 `NULL` 视为互不相同，因此根分类（`parentId` 为 `null`）重名还需要在业务层额外检查。

### 4.2 `Bookmark` 应包含的字段

| 字段 | 建议类型 | 说明 |
| --- | --- | --- |
| `id` | `Int` | 自增主键 |
| `categoryId` | `Int` | 必填，指向任意层级的分类 |
| `category` | 关联 | 所属分类，删除策略使用 `Restrict` |
| `name` | `String` | 收藏名称，建议限制为 100 字符 |
| `description` | `String` | 收藏描述，建议限制为 500 字符 |
| `iconUrl` | `String?` | 图标 URL，最长 2048 字符 |
| `url` | `String` | 网站 URL，最长 2048 字符且唯一 |
| `sort` | `Int` | 排序值，默认 0 |
| `isVisible` | `Boolean` | 是否公开，默认 `true` |
| `createdAt` | `DateTime` | 创建时间 |
| `updatedAt` | `DateTime` | 更新时间 |

建议索引：

- `categoryId + sort`
- `isVisible + sort`

### 4.3 Prisma 无法直接保证的规则

以下规则不能只依赖 Prisma Schema，必须由 API 业务逻辑校验：

- 父分类必须存在。
- 分类不能把自己设为父分类。
- 分类更新不能形成环（沿父链向上回溯时不能遇到自己）。
- 同一父分类下分类名称不能重复（根分类的 `parentId` 为 `null`，需在业务层额外查重）。
- 目标分类必须存在，收藏才能写入。
- 存在子分类或收藏的分类不能删除。

## 7. 第四阶段：收藏分类后台 API

### 7.1 接口列表

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/admin/bookmark-categories` | 获取完整分类树和数量 |
| `POST` | `/api/admin/bookmark-categories` | 创建分类（任意层级） |
| `PUT` | `/api/admin/bookmark-categories/:id` | 修改分类 |
| `DELETE` | `/api/admin/bookmark-categories/:id` | 删除空分类 |

### 7.2 创建分类时的校验顺序

1. 使用 Zod 校验请求体。
2. `parentId` 为空时创建根分类。
3. `parentId` 有值时查询父分类，不存在返回 `404`。
4. 检查同级分类名称是否重复。
5. 创建并返回数据，状态码为 `201`。

层级不限，因此不再有“父分类必须没有父级”这一条。

### 7.3 更新分类时必须检查

- 分类是否存在。
- `parentId` 是否指向自身。
- 新父分类是否存在。
- 修改是否会形成环（从新父分类沿父链向上回溯，不能遇到当前分类）。
- 新位置是否已经有同名分类。

涉及多次读取与写入时，建议使用 Prisma transaction，避免校验完成后数据被并发修改。

### 7.4 删除分类时必须检查

- 分类不存在：返回 `404`。
- 分类仍有子分类或有收藏：返回 `409`。
- 只有空分类可以删除，成功返回 `204`。

不区分层级——任何层级都遵循「空的可删、非空的拒删」。不要在这个功能中使用级联删除。

### 7.5 建议错误码

| 错误码 | HTTP 状态 | 场景 |
| --- | --- | --- |
| `INVALID_ID` | 400 | 路由 ID 无效 |
| `VALIDATION_ERROR` | 400 | 请求体校验失败 |
| `BOOKMARK_CATEGORY_NOT_FOUND` | 404 | 分类不存在 |
| `BOOKMARK_CATEGORY_CONFLICT` | 409 | 同级名称重复 |
| `BOOKMARK_CATEGORY_NOT_EMPTY` | 409 | 删除非空分类 |
| `BOOKMARK_CATEGORY_INVALID_PARENT` | 409 | 父级非法（自身或形成环） |

错误响应继续使用现有 `apiError()` 和 `zodFields()`。

## 8. 第五阶段：收藏后台 API

### 8.1 接口列表

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/admin/bookmarks` | 获取收藏，可按分类筛选（返回带 `categoryPath` 的扁平数组） |
| `POST` | `/api/admin/bookmarks` | 新增收藏 |
| `PUT` | `/api/admin/bookmarks/:id` | 修改收藏 |
| `DELETE` | `/api/admin/bookmarks/:id` | 删除收藏 |
| `PATCH` | `/api/admin/bookmarks/reorder` | 批量调整排序（`{ entries: [{ id, sort }] }`） |

### 8.2 创建和更新收藏的校验顺序

1. 使用 Zod 校验请求体。
2. 查询 `categoryId` 对应分类。
3. 分类不存在时返回 `404`。
4. 检查网站 URL 是否已存在。
5. 写入收藏。

分类层级不限，因此不再要求「必须挂在二级分类下」。

更新时检查 URL 冲突必须排除当前收藏自身。

### 8.3 查询规则

后台列表建议支持以下可选查询参数：

- `categoryId`
- `q`：名称、描述或 URL 模糊查询
- `visible`

列表结果是**扁平数组**，每项额外带 `categoryPath`（例如 `开发资源 / 设计工具 / 配色`），由 `server/utils/bookmarks.ts` 的 `withCategoryPaths()` 计算，前端直接展示完整路径，不需要自己拼树。

### 8.4 建议错误码

| 错误码 | HTTP 状态 | 场景 |
| --- | --- | --- |
| `BOOKMARK_NOT_FOUND` | 404 | 收藏不存在 |
| `BOOKMARK_CATEGORY_NOT_FOUND` | 404 | 指定分类不存在 |
| `BOOKMARK_URL_CONFLICT` | 409 | 网站 URL 已存在 |
| `BOOKMARK_REORDER_CONFLICT` | 404 | 部分收藏已不存在，请刷新后重试 |

### 8.5 拖拽排序接口（`PATCH /api/admin/bookmarks/reorder`）

请求体是**排序值对**而不是纯 id 数组：

```ts
const reorderSchema = z.object({
  entries: z.array(z.object({
    id: z.number().int().positive(),
    sort: z.number().int().min(-9999).max(9999),
  }).strict()).min(1).max(200),
}).strict()
```

为什么不是 `{ ids: number[] }`：分类之间、以及筛选后的可见行之间会有隐藏行，按「第 N 位 = N」重排会连带改到看不见的行。前端只在**当前可见范围**内取原本占用的 `sort` 槽位（`slots = scope.map(s => s.sort).sort()`），再把槽位依次分配给新顺序，隐藏行与其他分类的数字保持不动。

## 9. 第六阶段：前台公开查询 API

公开接口建议为：

```text
GET /api/bookmarks
```

接口只返回 `isVisible = true` 的收藏。排序在每一层各自生效：

1. 同一父分类下，子分类按 `sort` 升序、`id` 升序。
2. 同一分类下，收藏按 `sort` 升序、`id` 降序（新建的排前面，方便拖拽后新条目落在可见位置）。
3. 深度不限，每一层都遵循这两条。

实现方式是**一次查询 + 内存组树**：先按 `[{ sort: 'asc' }, { id: 'asc' }]` 取出全部分类（每个分类内嵌它自己的可见收藏），再用 `Map<id, node>` 按 `parentId` 挂树；找不到父节点的分类视为根。这样只发一条 SQL，分类数量增加也不会产生 N+1。

建议直接返回前端需要的树形结构（任意深度）：

```json
{
  "data": [
    {
      "id": 1,
      "name": "开发资源",
      "parentId": null,
      "children": [
        {
          "id": 2,
          "name": "设计工具",
          "parentId": 1,
          "children": [
            {
              "id": 5,
              "name": "配色",
              "parentId": 2,
              "children": [],
              "bookmarks": [
                {
                  "id": 1,
                  "name": "示例网站",
                  "description": "网站用途说明",
                  "iconUrl": null,
                  "url": "https://example.com"
                }
              ]
            }
          ],
          "bookmarks": []
        }
      ],
      "bookmarks": []
    }
  ]
}
```

注意事项：

- 不返回后台专用字段（`sort`、`isVisible`、`createdAt` 等）。
- 不返回隐藏收藏。
- 递归剔除「既没有可见收藏、也没有子节点」的分支（`prune()`），空分类不会出现在前台。
- 一次嵌套查询即可，避免 N+1。

## 16. 数据模型代码示例

收藏通过 `categoryId` 关联分类，两个外键都采用 `Restrict`，避免删除分类时误删子分类或收藏：

```prisma
model BookmarkCategory {
  id        Int                @id @default(autoincrement())
  name      String             @db.VarChar(50)
  parentId  Int?
  parent    BookmarkCategory?  @relation("BookmarkCategoryParent", fields: [parentId], references: [id], onDelete: Restrict)
  children  BookmarkCategory[] @relation("BookmarkCategoryParent")
  sort      Int                @default(0)
  bookmarks Bookmark[]

  @@unique([parentId, name])
  @@index([parentId, sort])
  @@index([sort, id])
}

model Bookmark {
  id          Int              @id @default(autoincrement())
  categoryId  Int
  category    BookmarkCategory @relation(fields: [categoryId], references: [id], onDelete: Restrict)
  name        String           @db.VarChar(100)
  description String           @db.VarChar(500)
  iconUrl     String?          @db.VarChar(2048)
  url         String           @unique @db.VarChar(2048)
  sort        Int              @default(0)
  isVisible   Boolean          @default(true)

  @@index([categoryId, sort])
  @@index([isVisible, sort])
}
```

示例省略了 `createdAt` 和 `updatedAt`，完整定义以 `prisma/schema.prisma` 为准。

## 17. Zod 校验代码示例

### 17.1 只允许 HTTP/HTTPS

`.url()` 只验证字符串是否符合 URL 语法，不代表协议一定安全，因此继续检查协议：

```ts
const httpUrl = (label: string) => z.string()
  .trim()
  .min(1, `请输入${label}`)
  .max(2048)
  .url(`${label}格式不正确`)
  .refine((value) => {
    const protocol = new URL(value).protocol
    return protocol === 'http:' || protocol === 'https:'
  }, `${label}只支持 HTTP 或 HTTPS`)
```

### 17.2 把空图标转换成 `null`

数据库使用 `null` 统一表示没有图标，避免同时出现空字符串和 `null`：

```ts
const nullableIconUrl = z.union([
  z.literal(''),
  z.null(),
  httpUrl('图标 URL'),
]).transform(value => value || null)
```

## 18. 分类业务规则代码示例

### 18.1 阻止自身与环

层级不再受限，所以不需要「防三级」，只需要挡住自身和环。更新父级时从新父分类沿父链向上回溯，途中遇到当前分类就说明会成环：

```ts
if (input.parentId === id) {
  // 返回 409 BOOKMARK_CATEGORY_INVALID_PARENT
}

let cursor: number | null = input.parentId
const visited = new Set<number>()
while (cursor !== null) {
  if (cursor === id) {
    // 返回 409 BOOKMARK_CATEGORY_INVALID_PARENT（会形成环）
  }
  if (visited.has(cursor)) break   // 数据已损坏时避免死循环
  visited.add(cursor)
  const parent = await tx.bookmarkCategory.findUnique({
    where: { id: cursor },
    select: { parentId: true },
  })
  if (!parent) {
    // 返回 404 BOOKMARK_CATEGORY_NOT_FOUND
  }
  cursor = parent.parentId
}
```

### 18.2 为什么同名检查要额外来一遍

PostgreSQL 的普通联合唯一约束会把不同的 `NULL` 看成互不相同，因此下面的数据库约束只能保证「同一父级下不重名」，对根分类（`parentId = null`）无效：

```prisma
@@unique([parentId, name])
```

创建和更新接口仍然显式查询，包括 `parentId = null` 的情况：

```ts
const duplicate = await tx.bookmarkCategory.findFirst({
  where: {
    parentId: input.parentId,
    name: input.name,
  },
  select: { id: true },
})
```

### 18.3 删除前检查内容

```ts
const category = await tx.bookmarkCategory.findUnique({
  where: { id },
  include: {
    _count: { select: { children: true, bookmarks: true } },
  },
})

if (category._count.children > 0 || category._count.bookmarks > 0) {
  // 返回 409 BOOKMARK_CATEGORY_NOT_EMPTY
}
```

应用层检查用于给出清晰错误提示，数据库中的 `onDelete: Restrict` 则是最后一道保护。

## 20. 公共接口组树示例

公开接口一次查询取回全部分类（每个分类内嵌自己的可见收藏），再在内存里按 `parentId` 组树、递归剪枝：

```ts
const rows = await prisma.bookmarkCategory.findMany({
  orderBy: [{ sort: 'asc' }, { id: 'asc' }],
  select: {
    id: true,
    name: true,
    parentId: true,
    bookmarks: {
      where: { isVisible: true },
      orderBy: [{ sort: 'asc' }, { id: 'desc' }],
      select: { id: true, name: true, description: true, iconUrl: true, url: true },
    },
  },
})

type CategoryNode = (typeof rows)[number] & { children: CategoryNode[] }
const nodes = new Map<number, CategoryNode>()
for (const row of rows) nodes.set(row.id, { ...row, children: [] })

const roots: CategoryNode[] = []
for (const node of nodes.values()) {
  const parent = node.parentId === null ? null : nodes.get(node.parentId)
  if (parent) parent.children.push(node)
  else roots.push(node)          // 找不到父节点时视为根，避免数据损坏导致整树丢失
}

function prune(items: CategoryNode[]): CategoryNode[] {
  return items
    .map(item => ({ ...item, children: prune(item.children) }))
    .filter(item => item.bookmarks.length > 0 || item.children.length > 0)
}

return { data: prune(roots) }
```

这种写法只有一条 SQL，不会随着分类数量增加而额外循环查询数据库，可以避免 N+1 查询；深度不限也不会增加查询次数。

## 21. 前端图标降级示例

后端只保存图标地址。前端记录加载失败的收藏 ID，并切换到默认图标：

```vue
<script setup lang="ts">
const brokenIcons = ref(new Set<number>())

function markIconBroken(id: number) {
  brokenIcons.value = new Set([...brokenIcons.value, id])
}
</script>

<template>
  <img
    v-if="bookmark.iconUrl && !brokenIcons.has(bookmark.id)"
    :src="bookmark.iconUrl"
    alt=""
    @error="markIconBroken(bookmark.id)"
  >
  <UIcon v-else name="i-lucide-globe-2" />
</template>
```

创建新 `Set` 而不是直接修改旧集合，是为了确保 Vue 能可靠追踪状态变化并重新渲染。
